## 当前基线与已确认约束

- 已完成：BattleManager 场景入口、唯一 ProjectileWorld、双方伤害结算、普通与散射武器、鼠标瞄准／射击、现有输入绑定、暂停与音乐同步、离线音频解析与候选点、八类预设的关键帧调度。
- 已确认：一个子母弹片段最多一个发射点、一个分裂点；子弹不再分裂。需要多个时间点出生时，使用多个子母弹片段。
- 已确认：角色跟踪弹优先 Boss；能量球由玩家主动瞄准射击，不自动抢锁。
- PDF 明确：武器仅在进入战斗前更换；无弹药容量限制。运行时活跃实体容量是性能保护，与弹药容量是不同配置。
- PDF 明确：能量球生命值为 1；爆炸前可击碎，击碎累计连击；未击碎则膨胀并向周围发射一圈弹幕。两类可弹反的追踪弹必须与两种技能的颜色和图标对应，提供五档难度预设。
- 角色武器初版数值：常规 10 伤害／5 次每秒／1 弹；散射 5 伤害／2.5 次每秒／5 弹；跟踪 4 伤害／8 次每秒／1 弹。弹速仍需配置与确认。
- PDF 的来袭弹伤害表另列普通弹 1、特殊弹 1.5–2；特殊弹具体采用哪个值、哪些模板属于特殊弹仍需明确，与角色武器伤害分别配置。
- 场景继续使用 GameplayPlaceholder，音乐继续使用 Remembrance；不引入旧资产兼容逻辑。

当前基线的说明见[第一阶段接入说明](战斗第一阶段与音频解析-接入说明.md)和[片段关键帧方案](片段关键帧发射与分裂-设计方案.md)。系统已有设置、HUD、输入和局外存档服务；缺的是具体业务接入，不是重做这些服务。

## 第二阶段：能量球与击碎结算

保留单次子母弹片段，在母弹模板中增加交互类别和能量球配置。能量球仍由 ProjectileWorld 管理，不另建一套独立弹幕容器。

发射点决定出生；一次发射可以生成配置数量的母球，并在指定区域内用已有固定随机流选择位置。多次随音乐出现，通过多个片段编排。分裂点决定未击碎母球的爆炸；膨胀进度按发射点到分裂点的区间计算，视觉尺寸与可击碎判定半径分别配置。子弹沿当前分裂配置形成环形弹幕。

修改边界：

- ProjectileDefinition：交互类别、能量球生命与膨胀／判定配置。
- DanmakuClip／EmissionSettings：明确的出生位置策略和随机区域配置，不用随机偏角代替随机位置。
- ProjectileWorld：能量球状态、半径更新、玩家弹到能量球的连续碰撞候选与接触去重。普通敌弹继续按原规则处理。
- CombatTypes：接触明确记录双方实体及目标种类，不继续将“非玩家目标”一概当作 Boss。
- CombatResolver：统一处理玩家弹击碎能量球、命中次数消耗与击碎去重。
- 建议增加 CombatComboState：计数状态；扩展 BattleEvent 发布 EnergyOrbDestroyed／ComboChanged 等值快照，表现层订阅。

宽相位应只生成允许交互的候选；小规模能量球可作为少量特殊目标。数量较多时采用空间网格，并让候选覆盖双方扫掠路径，避免全体子弹两两检测或只检查帧末重叠。

**需确认的边界**：当前分裂在本 Tick 运动和碰撞之前执行，所以击碎必须在分裂 Tick 开始前完成。如果希望“同 Tick 射中与爆炸时击碎优先”，需要明确修改爆炸提交时序，并重新定义子弹出生／推进时间与 Seek 语义，不能沿用现有测试结果宣称已支持。

尚需设计输入：随机区域、出生保护距离、膨胀尺寸及判定曲线、母球是否伤害角色、连击重置／超时／奖励规则。可先实现单纯累计计数；未确认前不自动加入重置或奖励。

## 第三阶段：跟踪武器与战前配置

建议增加 ProjectileMovementSettings／ProjectileMotion（名称可按项目风格调整），把“持续调整飞行方向”与“发射时瞄准”区分。使用 FP64 和固定 Tick 更新方向，转向速率、速度、追踪时长、丢失目标策略均可配置；角色和敌方追踪弹复用运动计算，目标策略分别配置。

角色跟踪弹选择存活 Boss，排除能量球。Boss 消失后的飞行／回收行为需明确，不自行切换到能量球。普通和散射仍按鼠标方向发射。

战前选择通过现有系统的关卡进入流程传入选中的武器 ID；BattleSimulation 创建时固定选择，暂停也属于战斗中，不能借暂停菜单换武器。具体选择界面放在哪个已有页面需核对界面设计。

所有武器数值需要表格配置。建议使用编辑器 CSV 导入生成现有 SO：CSV 是数值来源，SO 是运行时产物，避免两处独立修改。新增 WeaponTableImporter，校验稳定 ID、枚举、数量、有限数值和重复行；不把当前已存在的可编辑 SO 误称为已完成表格管线。

需要确认：转向与弹速、追踪时长、丢失 Boss 策略、战前选择入口及正式跟踪弹 Sprite。

## 第四阶段：跳跃、飞行、冲刺

复用现有 JumpFly、Dodge 和左右移动，不新建输入资产，也不直接读取 Keyboard。建议扩展 BattleInput 的按下／释放／持续状态，将指令缓冲转换为固定 Tick 输入；跨无 Tick 帧保留，补多个 Tick 时一次性动作只消费一次。

现有 JumpFly 的 HeldSeconds 在渲染帧更新，不能直接作为要求重演一致的飞行判定时间源；长按计时应在模拟 Tick 中进行。

由玩家运动模块管理地面／腾空／飞行／冲刺状态、体力和受击状态。技能状态在本 Tick 移动与碰撞之前提交，IHudDataSource 输出实际体力。SystemRoot 的输入／UI 指令分发与 HUD 请求必须汇入同一缓冲，避免快捷键与 UI 重复执行。

实施前需确认：跳跃曲线、地面和落地规则、长按转飞行阈值、飞行控制、冲刺方向／距离／时长、是否无敌、体力消耗与恢复、移动能力与弹反的互斥规则。PDF 只提出这些能力，没有足够参数支持直接落实。

## 第五阶段：双技能弹反与五档难度

建议增加 ParryDefinition／ParryState／ParryDifficultyPreset，并在子弹上配置可弹反标签。标签统一关联技能 ID、颜色、图标，不通过比较 Sprite 或浮点颜色判断匹配。

Skill1／Skill2 沿用现有可改键输入。按键及 HUD 技能按钮都只发出同一种请求，由 BattleSimulation 在固定 Tick 内开启判定窗口。CombatResolver 根据接触时间、标签、技能窗口及存活状态结算；弹反后避免同一弹继续造成角色伤害或重复命中 Boss。

当前 BattleManager 调用 AttachGameplay 时技能请求接收器为 null；需要把实际 IGameplayRequestSink 接入，并将输入指令及按钮请求导向唯一缓冲。已有图标与输入 Action 不代表技能业务已完成。

角色跟踪弹的优先 Boss 约定不等于敌弹追踪目标；敌方可弹反弹幕追踪玩家，复用第三阶段运动计算。

五档难度使用明确预设，字段可以涵盖弹速、追踪参数、发射密度和有效窗口。具体哪些维度变化、各档数值及同 Tick 多弹规则需确认，不能仅改五个名字作为完成。

必须确认：弹反窗口与冷却、错色／提前／过晚的结果、成功后是原弹转向回击还是消弹并直接扣 Boss 生命、回击伤害、体力消费以及与冲刺无敌的先后关系。

## 第六阶段：完整关卡、HUD 与交付

根据 Remembrance 的候选点人工编排攻击段，组合普通弹、能量球、两类可弹反弹幕及五档难度，继续采用片段条上的显式发射／分裂点。候选点只是辅助，不自动当作已确认的关卡节奏。

沿用现有 HUD 数据入口，补充连击、真实体力与技能可用状态。Boss 血条、胜负界面和能量球预警属于建议的完整关卡交付项，需核对布局；它们不是当前 PDF 已给出的完整 UI 规格。

资源方面需要正式角色／Boss／球／跟踪弹 Sprite、技能图标及特效／音效；缺少时用明确可替换的占位资源，不猜测正式资产路径。整首攻击节奏、出生安全区、难度与武器平衡需人工试玩。

验收覆盖编辑器与实战一致、Pause／Seek／循环、不同渲染帧率下相同输入重演、胜负、活跃实体峰值、空间候选数量和目标 PC 构建。已有设置与局外存档可以复用；武器解锁／局外养成字段只有需求明确后才接 IProgressDataProvider，不保存局内弹幕快照。

## 可复制的参考实施文本

以下是未来阶段的任务文本，不代表本次已授权执行其中全部工作。每次可直接指定其中一阶段；已确认约束继续有效。

### 第二阶段任务

```text
实现第二阶段可击碎能量球与连击计数，沿用 GameplayPlaceholder、Remembrance、现有输入和关键帧系统。
每个子母弹片段最多一次发射、一次分裂；配置数量的母球在明确区域内随机出生，生命为 1，按发射到分裂的区间膨胀。
玩家弹可击碎能量球；已击碎母球不爆炸、不生成环形子弹，连击只累计一次。普通敌弹保持现有交互规则。
ProjectileWorld 负责状态与碰撞，CombatResolver 负责效果，BattleEvent 输出击碎及连击结果；不建立第二套弹幕世界。
先核对爆炸与命中同 Tick 的先后、母球接触伤害、随机区域和膨胀配置；连击重置及奖励未经确认不加入。
验证高速命中、同 Tick 多弹、击碎与爆炸边界、清弹、子弹池复用、片段隔离及 Seek 一致。需要人工配置时指出具体对象与字段，不猜测路径或玩法参数。
```

### 第三阶段任务

```text
实现跟踪运动、战前武器选择和角色武器 CSV 配置导入，复用现有 ProjectileWorld 与武器资产。
角色跟踪弹自动锁存活 Boss，不锁能量球；普通和散射按鼠标瞄准，射击沿用现有 Fire 动作。
数值采用常规 10/5/1、散射 5/2.5/5、跟踪 4/8/1（伤害/每秒次数/每次弹数），弹速与转向等未定项先核对。
武器仅在进入战斗前选择，创建模拟时固定；战斗中和暂停中都不能更换。不增加弹药容量机制。
CSV 导入校验 ID、数值与重复项，生成运行时 SO。先确认战前界面入口、无 Boss 时策略和正式跟踪弹资源。
验证目标排除、转向限制、目标死亡、射速、暂停、重演、战中拒绝切换以及表格导入失败处理。
```

### 第四阶段任务

```text
实现已确认规则下的跳跃、长按飞行、冲刺与体力，接入现有 JumpFly、Dodge 和左右移动输入。
开始写具体运动前，核对跳跃/落地、长按阈值、飞行控制、冲刺方向与时长、无敌以及体力消耗恢复规则。
将动作转为固定 Tick 的 BattleInput；一次性指令只消费一次，长按时长在模拟中计数，暂停不累计。
运动与防御状态在碰撞前提交，HUD 读取真实状态；键盘与 UI 请求走同一输入缓冲。
验证边界、地面/飞行转换、体力耗尽、暂停恢复、改键和不同渲染帧率的重演一致性。不猜测未确认的数值。
```

### 第五阶段任务

```text
实现两类追踪弹、对应 Skill1/Skill2 的弹反及五档难度，复用现有输入、追踪运动和 CombatResolver。
用稳定技能标签统一弹幕与技能的颜色/图标，正确标签和有效窗口才能成功；输入与 HUD 点击只提交请求。
先核对窗口、冷却、失败结果、成功后的回击方式和伤害、同 Tick 多弹及与冲刺无敌的先后，再落实代码。
五档难度必须由可配置参数产生实际差异，具体参数先确认；保持每个子母弹片段单次发射/分裂约束。
验证正确/错误标签、窗口边界、重复接触、同 Tick 受伤冲突、Boss 死亡、暂停、改键、重演及各难度配置。
```

### 第六阶段任务

```text
在 GameplayPlaceholder 与 Remembrance 中接入已完成机制，制作完整可验收关卡。
人工按音乐候选点编排普通攻击、能量球和可弹反追踪弹，使用片段内显式关键帧；多次子母弹用多个片段。
接入连击、体力、技能状态，并先核对 Boss 血条和胜负界面的布局。正式资源缺失时明确使用占位并列出资源位置。
继续沿用现有输入、HUD、暂停、音量和场景流程；武器仅战前选择。局外字段未确认前不扩展存档内容。
完成整曲试玩、节奏和难度检查、暂停/循环/重演、容量和候选对性能、目标 PC 构建及回归记录。
需要人工调整攻击节奏、数值或素材时提供具体资产/字段清单，不自动猜测最终关卡设计。
```
