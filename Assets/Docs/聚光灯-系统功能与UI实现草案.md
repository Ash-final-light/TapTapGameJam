# 聚光灯：系统功能与 UI 实现草案

日期：2026-10-06。阶段：设计已批准并落地；本文保留实施前的设计依据，实际入口和接入说明见《聚光灯-系统实现与使用说明.md》。

本文依据《聚光灯-系统.pdf》、其中的界面原型图、用户提供的键位与分辨率截图，以及本次需求确认记录。用户明确的选择优先于原稿中的冲突描述。用户批准实施后，已新增系统运行时代码、独立输入资产、配置、可编辑 UI Prefab 与场景；类名和职责合并以实际代码为准。

## 1. 已确认范围

| 项目 | 确认结果 |
| --- | --- |
| 平台 | 首版仅 PC，键盘/鼠标操作 |

| 音频设备 | B：音量功能落地，设备选择和麦克风提供 UI/状态接口，实际设备能力后续接入 |

## 2. 键位与设置项

### 2.1 动作清单

| 动作 | 默认键 | 行为 |
| --- | --- | --- |
| 左移动 | A | 持续输入，发布方向状态 |
| 右移动 | D | 持续输入，发布方向状态 |
| 跳跃 | Space | 发布按下请求 |
| 飞行（长按） | Space | 发布持续按住状态；具体飞行触发阈值由业务层确定 |
| 闪避 | Shift | 发布闪避请求 |
| 技能 1 | Q | 发布技能 1 请求 |
| 技能 2 | E | 发布技能 2 请求 |
| 道具选择栏 | Tab | 按住显示，松开关闭 |
| 道具使用栏 | R | 请求使用当前选中道具 |
| 暂停 | Esc | 固定系统操作，不允许重绑定 |

除固定系统操作外支持修改键位、应用保存、重启读取和恢复默认。主键盘数字键负责选择栏内的槽位，不额外加入未请求的上下移动、低速移动、射击或 Bomb 设置项。

**设计约定，仍可调整：**跳跃/飞行暂采用共用绑定组，设置页保留两行，修改其中一行同步更新另一行，避免破坏原图的共键设计；此组合不触发普通冲突提示。其他业务动作之间的重复键拒绝保存并给出冲突对象。Tab 与 R 是默认值，运行时查询实际绑定，不硬编码这两个按键。

### 2.2 显示设置

- 分辨率：512×288、768×432、1024×576、1280×720、1334×750、1366×768、1536×864、1600×900、1920×1080、2048×1152、2560×1440。
- 帧率上限：1、5、10、20、30、60、120、无限制；默认 60。
- 显示模式：窗口、全屏、无框窗口；开发环境默认窗口，发布版本默认全屏。
- 默认分辨率跟随显示器推荐值；若不在固定列表，显示当前/推荐项，避免首次进入时擅自切为最低分辨率。
- 下拉列表均为单选，方框外观参考原图；不支持的显示组合置灰。支持性按显示模式判断，窗口模式不能只用显示器的全屏模式列表过滤。
- 帧率上限与显示器刷新率分开处理；处理 VSync 对限帧的影响，验收实际渲染节奏，不改变逻辑 TickRate。

### 2.3 声音设置

总音量、背景音乐、音效为 0～100 整数，默认 100。总音量作用于音乐和音效，子通道各自控制比例；0 对应静音。采用统一音量服务管理注册的 AudioSource，后续可以在同一接口后替换为 AudioMixer 实现。

**第四项的设计约定，仍可调整：**UI 暂显示“音量比例”，数据字段为 `VolumeScale`，默认 1；控件显示 0～100，读取时转换为 0～1。首版完成设置、持久化及变更通知，不把它重复乘到已经受总音量控制的音乐/音效上，也不先假定它属于某个已有语音服务。后续消费模块明确目标后再命名和接线。

音频输入/输出保留原图中的两行，显示“跟随系统（后续接入）”，控件禁用，不提供无实际效果的设备列表。麦克风由外部数据接口提供 Off/On/Unavailable 等状态，首版默认关闭，不请求录音权限。

使用 uGUI 与 TextMeshPro。占位图包括背景、头像、满血/空血、技能 1/2、道具、麦克风状态；通过序列化引用替换。加载动画在缺少正式序列帧时使用清晰标注的简单占位动画，不能将正式角色跑动资源列为已交付。

Canvas 使用 Scale With Screen Size，参考尺寸暂定 1920×1080；锚点与 LayoutGroup 管理布局。复用当前项目 SafeArea，背景铺满，交互内容保持在有效区域内。设置页和键位页在低分辨率下允许滚动，底部操作按钮仍可访问。文本使用可显示中文的 TMP 字体资源；在实施时核查项目字体覆盖与资源引用。

控件均可在场景/Prefab 中编辑；非交互图片不拦截射线；每个运行场景保持一个有效 EventSystem 和 InputSystemUIInputModule。

## 4. 场景与窗口流程

建议保留并完善现有 `Assets/Scenes/Title.unity`，新增 `Loading.unity` 与 `GameplayPlaceholder.unity`。配置资产保存实际关卡入口，后续可以用正式关卡替换占位入口，不修改菜单逻辑。

流程：

```text
Title
  开始 → 有进度时覆盖确认 → Loading → 新手关卡/占位关卡
  继续 → 有效局外存档及关卡入口 → Loading → 关卡起点
  设置 → Settings → 关闭后回到 Title
  退出 → 关闭进程；Editor 中停止播放

GameplayPlaceholder/正式关卡
  Esc 或暂停按钮 → Pause
  Pause → 继续 → 恢复局内
  Pause → 设置 → Settings → 关闭后回到 Pause
  Pause → 保存 → 保存局外数据，显示结果，保持暂停
  Pause → 退出 → 关闭进程，局内状态不持久化
```

主菜单只初始化系统设置、读取存档有效性，不预加载关卡。防止重复点击触发多个加载请求；选择取消新游戏覆盖时不修改存档。新游戏重置养成/关卡记录，保留显示、声音和键位设置；建议在目标入口可用后提交新进度，避免加载失败先丢失旧进度。

加载状态分为准备、加载、激活、完成、失败。使用不受暂停影响的时间更新动画及最少展示 1 秒的计时；进度包含场景激活/初始化，不在未完成时显示 100%。超过 3 秒持续反馈进度；加载失败显示原因与重试。超时不代表异步操作自动取消，旧请求仍在执行时不能再并发启动第二个加载，重试必须受请求状态保护。

暂停通过统一服务暂停已注册的局内运行器，并切换 Gameplay/UI 输入；菜单和加载动画继续更新。优先适配现有 DanmakuSequencePlayer.Pause/Resume，记录暂停前是否播放，不无条件恢复原本已停止的对象。设置窗口从暂停进入时不会擅自解除暂停。隐藏道具栏并清理一次性输入；恢复时重新检查实际按键状态，避免残留 Tab 或 R 输入。

## 5. 设置编辑与键位重绑定

设置采用三份概念状态：默认配置、已应用/保存值、当前编辑草稿。进入界面时从已保存值复制草稿。

- 切换页签保留同一次打开期间的草稿；关闭后丢弃未应用改动。
- 音量滑动即时预览；显示模式/分辨率/FPS 在应用时改变。
- 重绑定修改草稿输入资产，不先改变实际 Gameplay 绑定；应用后统一提交。
- 重置将整个设置草稿恢复默认值，尚不写盘；声音可试听默认值，取消仍恢复此前已保存的音量。
- 应用先验证值与键位冲突，再应用并保存；成功后更新基线，继续停留设置页。
- 取消/关闭/Esc 丢弃草稿并回滚试听；应用之后再取消不会撤销此前已经保存的设置。
- 保存失败显示错误并保持编辑状态，不显示“保存成功”；记录并恢复必要的运行设置，避免磁盘与实际状态悄悄不一致。

重绑定时显示等待提示，暂禁其他动作。Esc 只取消本次等待，不绑定为业务键；若正在等待输入，第一次 Esc 不同时关闭整个设置页。点击进入等待的鼠标事件不作为新绑定。关闭界面时释放重绑定操作并清理事件订阅。

官方推荐列保留只读样式，原稿已有五行使用其示例显示内容；新增技能和道具行先显示“—”，不自行发明推荐键，也不让该列影响真实输入。

## 6. HUD 与道具的数据契约

建议通过 `IHudDataSource` 提供快照与变更通知，UI 只消费显示数据。字段涵盖：

| 数据 | UI 行为 |
| --- | --- |
| Portrait | 更新左上头像 |
| Health/MaxHealth | 初始调试值 5/5；生成对应数量血格，左至右填充，掉血从右向左，显示过渡状态 |
| Stamina/MaxStamina | 初始调试值 100/100；更新竖槽比例，低于 30% 使用警示色；实际消耗/恢复由外部数据驱动 |
| Skill1Color/Skill2Color | 使用同一颜色值更新技能图标/提示，供 Boss 弹幕表现共享，避免分别填两份近似颜色 |
| Items | 稳定 ItemId、图标、数量、是否可用；零数量从选择栏隐藏 |
| SelectedItemId | 左上装备信息与使用栏保持一致，选择栏显示对应边框 |
| MicrophoneState | 开启常亮、关闭置灰、不可用/未授权明确标识 |
| Warning | 预警文本/图标与世界位置或屏幕锚点，显示在角色附近/战斗区域，避免遮挡关键判定位置 |

UI 向业务发布 `SelectItemRequested(itemId)`、`UseItemRequested(itemId)`、`SkillRequested(index)` 等请求。使用后不由 UI 自行扣数量；接收业务返回的最新状态。技能、跳跃、飞行、闪避输入由独立业务输入接口发布。

按住实际“道具选择栏”绑定显示弹窗，数字键按当前可见列表顺序选择；没有可用道具时显示空状态。松开选择键关闭弹窗并保留选择。选择项数量变 0 或被移除时，暂按“选择剩余列表第一项，没有则清空”的规则更新，作为可调整的实现约定。按使用键且无选中/可用道具时不发布无效使用请求。

数字键展示与可见槽位映射一致。首版最多展示 10 个槽位（1～9、0），超过数量时明确提示配置超额，不默默让多余道具无法选择；后续分页需另定交互。

提供独立 `HudDebugDataSource` 和调试 Inspector，可改变血量、体力、颜色、道具数量、麦克风状态与预警，验证所有 UI。正式场景可以替换为实际数据源。默认调试数据不冒充玩家真实养成数据。

## 7. 存档与配置

设置与进度分开保存到 `Application.persistentDataPath` 下的文件。数据带 SchemaVersion；读取校验版本、必要字段及关卡 ID，损坏或不兼容时提示一次并按无有效存档处理，不加载任意场景路径。

- `SettingsData`：分辨率、显示模式、渲染 FPS、总/音乐/音效音量、VolumeScale、键位覆盖。
- `ProgressSaveData`：版本、关卡入口 ID、局外养成数据。通过 `IProgressDataProvider` 接收具体养成字段；首版调试提供者只能用于功能验证。
- 不保存子弹列表、玩家当 Tick 坐标、Boss 时序、当前体力或其他局内即时状态。
- 保存使用临时文件加替换/备份策略；操作结果返回 UI。暂停手动保存只写进度，不写未应用的设置。
- 默认设置与运行状态分离；运行时不修改 SO 模板作为“保存”。
- 自动保存暂在新游戏成功进入和关卡入口/局外数据明确提交时调用；其他养成事件通过业务接口显式请求保存。

配置资产建议包括：`SystemDefaults`、`LevelEntryCatalog`、`LoadingTipConfig`、`UIPlaceholderTheme`。加载提示需支持表格导入（例如 CSV：Id/Text/Weight/Enabled），可导入 SO 供运行时使用；不要求复用参考项目完整 CSV 框架。

## 8. 模块划分与参考复用

以下名称为拟定职责，不表示源码已存在。

| 模块 | 责任 |
| --- | --- |
| SystemRoot | 初始化设置、存档、音量、窗口与场景流程；跨场景保持单实例 |
| SettingsService/SettingsDraft | 设置读写、验证、应用、编辑和取消回滚 |
| BindingService | 默认键、覆盖、冲突、共键组、保存与恢复 |
| AudioVolumeService | 音乐/音效/总音量、试听及 scale 通知 |
| ProgressSaveService | 局外存档有效性、读取、保存、新游戏重置 |
| SceneFlowService | 加载入口、防重复、进度、失败及重试 |
| WindowController/PauseService | 窗口层级、返回来源、输入 Map、局内暂停恢复 |
| MainMenuView/LoadingView/SettingsView/PauseView | 控件绑定与状态展示 |
| HudView/ItemSelectorView | 状态刷新、选择和业务请求 |
| GameplayCommandSource | 本轮动作绑定、持续状态与请求事件 |

参考 ARPG-Demo 的控件监听生命周期、设置缓存/通知与显示设置入口，参考 LuoProject 的键位覆盖 JSON、控制方案重置和音量反馈。按 PDF 重写“应用/取消”语义；不整体搬入 VContainer、原 GameApplication、旧 CSV/GameManager 或旧 Text 依赖。

当前项目没有已核实可用的运行时窗口管理器，采用小型窗口控制服务，不将已有 Windowing 编辑器调试文件当成运行时基础。复用现有屏幕适配组件。

新增系统输入资产暂命名 `SpotlightControls.inputactions`，避免立即覆盖旧 `DanmakuControls`：旧弹幕玩家有上下移动/Focus/Fire/Bomb，本轮动作有跳跃/飞行/闪避，两者语义不同。占位场景使用新资产；对接现有实际场景时通过明确适配器桥接 Pause 与业务状态，不将新动作强行映射为旧动作。现有 Motor 和模拟的 60 Hz 行为不因本轮限帧设置而改变。

## 9. 建议文件与 Prefab 结构

```text
Assets/Scripts/System/
  Runtime/            服务、DTO、接口与业务输入
  UI/                 界面控制脚本
  Editor/             配置导入、UI 搭建及验证工具
Assets/UI/Spotlight/
  Prefabs/            MainMenu、Loading、Settings、HUD、ItemSelector、Pause、Dialog
  Placeholders/       背景、图标、字体/动画引用
Assets/Configs/Spotlight/
                      默认设置、关卡入口、加载文案、UI 主题
Assets/Inputs/SpotlightControls.inputactions
Assets/Scenes/        Title、Loading、GameplayPlaceholder
```

通过 Unity Editor API 创建/修改场景、Prefab 和配置，先核对现有对象再接线；不手写场景 YAML。UI 资产采用 Inspector 序列化引用，减少依赖对象名字查找；构建列表最终加入以上入口场景。

## 10. 实施顺序与交付

1. **配置和接口**：默认设置、键位清单、HUD/进度契约、加载入口与文案配置；建立新输入资产及持久化服务。
2. **界面骨架**：按 PDF 搭建可编辑 Canvas/Prefab，接中文字体及占位图；完成三页签、滚动、按钮状态和弹窗层级。
3. **菜单与加载闭环**：开始/继续、存档异常、新游戏确认、加载时序、失败/重试、退出。
4. **设置完整行为**：显示设置、渲染限帧、声音试听/回滚、scale、重绑定与保存/恢复。
5. **HUD 与道具**：数据订阅、血格/体力/颜色、Tab 保持显示、数字选择、R 使用请求；接调试数据源。
6. **暂停与集成**：Esc、暂停按钮、设置返回路径、局外保存、现有播放器暂停适配。
7. **验收**：Unity 编译、关键逻辑验证、实际 UI 操作和 PC 构建；截图对照 PDF。

本轮最终交付应包含功能源码、可编辑界面 Prefab/场景、占位图资源、默认配置/输入资产、挂载说明、验证报告及 UI 截图；不能只交付运行时动态创建、无法在 Editor 中检查的界面。

## 12. 可调整约定

需求范围和用户指定默认键均已锁定。以下约定为草案实现选择，后续可单独调整，不阻止系统/UI 原型搭建：Space 共键组联动；第四项暂称“音量比例”并提供 0～1 scale；选中道具失效后回退第一项；首版数字槽位上限 10；新游戏保留个人设置并重置进度；参考分辨率 1920×1080。

## 13. 代码设计细化

本节回应“确认代码设计思路”，细化前述职责和实现方式；类名与签名为设计示意，尚未创建对应 C# 源码。若与前文概括存在差异，以本节的具体依赖和时序为准。

### 13.1 依赖方向与生命周期

采用“View → Controller → Service/业务接口”的依赖方向。配置和存储位于底层，不能反向引用界面。命名空间使用 `TapTap.Systems`、`TapTap.Systems.UI`、`TapTap.Systems.Editor`，避免命名为 `System`。

- `SystemRoot` 是一个 MonoBehaviour，作为单一初始化入口，显式创建普通 C# 服务并连接依赖。
- 设置、绑定、存档、窗口状态等服务不分别实现 MonoBehaviour 单例；不引入新的 DI 框架、全局事件总线或 UI 框架。
- 仅使用实际有替换需求的接口：HUD 数据源、业务命令接收器、进度提供者、暂停目标，以及可验证的显示/存储边界。
- 跨场景保留一个 `SystemRoot`、一个 UI 根节点和一个 EventSystem；入口场景中的重复根节点有单实例保护。Title、Loading 和关卡不各自同时持有生效的 EventSystem。
- 界面采用预制体序列化引用，首次创建后 `Bind(...)` 再显示；显示订阅、隐藏注销，退出设置会释放输入资产副本和重绑定操作。
- 普通 C# 对象使用明确的 Dispose/解绑流程，场景内数据源和暂停目标在卸载时取消注册，避免持有已销毁 Unity 对象。

UI 根节点只管理本项目需要的层：页面、HUD、弹窗、提示。首版不实现通用复杂窗口语言。Settings 记录进入来源，Dialog 返回下层窗口；层级决定谁接收 Esc 和键盘焦点。

### 13.2 设置数据和编辑会话

核心对象拟定为 `SettingsData`、`SettingsEditSession`、`SettingsService`、`BindingService`、`AudioVolumeService`。

```csharp
// 示意签名，不是已实现接口。
SettingsEditSession BeginEdit();
void ResetDraft(SettingsEditSession session);
void PreviewAudio(SettingsEditSession session);
ApplyResult Apply(SettingsEditSession session);
void Cancel(SettingsEditSession session);
```

`SettingsData` 是可序列化 DTO，包含 SchemaVersion、宽高、显示模式、渲染帧率、三个音量、VolumeScale、BindingOverridesJson。SO 只保存默认值。编辑会话持有独立 DTO 和输入资产副本，不能浅复制后共享可变数组或直接修改项目资产。

应用顺序为：校验草稿 → 保存旧运行状态 → 应用显示/音量/键位 → 确认实际接受值 → 写盘 → 更新已应用基线。失败则返回带原因的结果，保留编辑内容，并尝试恢复此前运行状态；显示回退失败也必须报告。显示切换如需等待下一帧确认，Apply 进入 Pending 状态并锁定重复提交，最终成功后才写入已接受值。API 示意中的 ApplyResult 因而应支持 Pending/Success/Failure。

声音试听只改变 AudioVolumeService 的预览状态；Cancel 恢复已应用声音。Apply 成功后继续编辑的基线是新设置。VolumeScale 有独立通知及读取入口，后续消费模块订阅，不隐式重复控制音乐和音效。

BindingOverridesJson 按 InputAction/Binding 的稳定 ID 存储；载入时校验结构及已知动作，只应用支持的键盘绑定。失效覆盖回退默认，不因一条坏数据让整个设置页无法打开。

### 13.3 系统输入与业务输入

`SystemInputRouter` 持有 `SpotlightControls` 的运行时克隆，拥有输入上下文切换权。UI 模块引用这一实例中的 UI actions，重绑定编辑则使用第二份草稿克隆，避免改键时影响真实 Gameplay。

系统输入不直接沿用现有 PlayerInputManager 的默认启动 Map：该管理器 Start 时会切回默认 Gameplay，可能覆盖主菜单 UI 状态。新路由明确初始化所需上下文，现有弹幕输入通过适配器接入，不改它的默认行为来迁就系统菜单。

| 逻辑动作 | 输入资产表示 | 消费方式 |
| --- | --- | --- |
| 左/右移动 | 分别可改的 Left/Right 绑定 | 汇总为水平轴状态，两键同时按暂按 0 处理 |
| 跳跃/飞行 | 暂使用一个 JumpFly action，对应设置页两行 | 输出 Pressed/Held/Released 与持续时间，业务层决定跳跃/长按飞行，不同时执行两个运动逻辑 |
| 闪避/技能 1/技能 2 | Dodge/Skill1/Skill2 | 缓冲一次性命令供业务消费 |
| 道具选择 | ItemSelect | 控制选择栏持续显示状态 |
| 道具使用 | ItemUse | 发布当前选中 ItemId 的使用请求 |
| 数字槽位 | 1～9、0 固定 UI 操作 | 仅选择栏打开且无模态窗口时接受 |
| 暂停/取消 | Gameplay Pause 与 UI Cancel 的 Esc | 由当前输入上下文和顶部窗口统一路由，一次按键只处理一个层级 |

局内模式允许 HUD 指针点击，打开菜单时禁用 Gameplay 指令。选道具是局内覆盖层，不切换成会禁用 ItemSelect 的普通菜单 Map，否则按住/释放的状态会被打断；它只增加槽位选择上下文。暂停、设置或失焦时清空选择栏保持状态和一次性命令。

提供 `GameplayCommandBuffer`：持续状态可重复读取，Pressed 命令入队，在业务逻辑 Tick 中消耗一次；无 Tick 的渲染帧保留命令，多 Tick 不重复消费。接入实际游戏时由现有游戏时钟消费，不新增并行的玩家时钟，也不在 InputAction 回调里改变角色位置。系统 UI 的打开/关闭无需等待业务 Tick，尤其暂停后的 UI Cancel 仍可执行。

重绑定期间只保留取消等待所需的输入；完成后先验证新键，再写入草稿。限制 Esc 及数字槽位保留键，提示冲突原因，避免技能或道具使用与槽位选择在同一上下文同时触发。点击开启重绑定的鼠标输入被排除。

### 13.4 HUD、道具状态与业务请求

采用 `HudSnapshot` 与 `ItemViewData` 保存显示状态；持久化进度 DTO 不包含 Sprite 等表现引用。`IHudDataSource` 提供 Current 和 Changed；`IGameplayRequestSink` 接受技能、道具及其他动作请求。

```csharp
// 示意签名。
HudSnapshot Current { get; }
event Action<HudSnapshot> Changed;
void RequestSkill(int skillIndex);
void RequestSelectItem(string itemId);
void RequestUseItem(string itemId);
```

`HudController` 订阅数据并更新各视图，`ItemSelectionController` 持有弹窗可见状态和数字槽位映射。选中 ItemId 的权威值由数据源提供；占位实现收到选择请求后可立即更新并通知，真实业务可拒绝请求或返回最新状态。UI 不直接修改库存对象，也不在发出使用请求时自行扣数量。

同一帧道具选择按稳定快照建立槽位映射，使用请求携带稳定 ItemId，不保存“第三个格子”作为道具身份。库存变化后重建映射并校验选中 ID。通常采用事件刷新，初次显示读取快照，避免每个 View 每帧查找同一数据源。

调试数据源单独实现以上契约，供占位场景验证五格血量、体力、道具数量、技能颜色及麦克风三态。调试自动响应和正式业务响应不混在 View 代码内。

### 13.5 暂停与窗口返回

使用 `IPauseTarget` 适配运行器，`DanmakuPauseAdapter` 包装现有播放器。暂停时记录目标原先的 Playing；恢复只恢复原本运行且当前仍有效的目标。

`PauseService.Acquire(reason)` 返回可释放的句柄；只在首个暂停理由出现时暂停，只在最后一个理由移除时恢复。Pause 窗口持有句柄，打开 Settings 不释放；关闭 Settings 返回 Pause；点击继续才释放 Pause 的句柄。卸载场景时清理场景所属目标/句柄。

窗口 Esc 路由顺序是：重绑定等待 → 顶层 Dialog → Settings 取消 → Pause 继续 → 局内打开 Pause。同一次输入只处理首个匹配项，防止“退出等待同时关闭设置”或“打开暂停后立即关闭”。系统 UI 和动画使用不受局内暂停影响的时间。

### 13.6 存档、场景流程及错误结果

`SettingsStore` 与 `ProgressSaveService` 分别写设置和进度文件，文件内容用 JsonUtility 可处理的 DTO；字典类型数据转为序列化列表。`IProgressDataProvider` 明确 Export/Restore/ResetNewGame 的边界，菜单不读取战斗组件字段拼存档。

`SceneFlowService` 使用一个受控状态机和一个有效请求 ID。按钮、存档入口或重试都调用同一入口；已经加载时返回 Busy，失效请求的回调不切换窗口。加载协程集中由 SystemRoot 的驱动组件运行，不由多个 View 各自启动协程。

设置/保存返回 Success/Failure，场景请求另含 Busy，存档检查返回 Missing/Valid/Corrupt/UnsupportedVersion；View 只依据结果更新按钮或提示，不靠解析异常文本判断业务状态。IO/导入错误保留日志信息，用户提示使用简洁中文。

### 13.7 UI 资产创建及必要验证

一个 Editor 搭建入口创建占位图、配置、Prefab 并接场景引用，所有结果实际保存到 Assets。搭建流程按界面分步骤执行，检查现有资产，不重复生成相同根节点，也不在 Play 时重建整套控件。运行时只负责加载 Prefab、绑定数据与显示隐藏。

验证集中于编辑会话保存/回滚、绑定冲突/Space 共键、命令一次消费、Tab 保持状态、道具 ID、暂停句柄、加载请求互斥和存档损坏处理。Prefab 通过实际 Unity 渲染与键鼠操作检查；不为每个简单按钮写重复包装测试。
