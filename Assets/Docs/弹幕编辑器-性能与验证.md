# 弹幕编辑器：性能与验证记录

日期：2026-10-02。第一版面向 PC／手机，使用固定测试玩家与 Sprite 表现。记录用于比较后续实现变化，不作为手机帧率承诺。

## 已实施的性能措施

普通子弹不创建 GameObject、Transform、MonoBehaviour、Unity Collider2D 或 Rigidbody2D。已有轻量定点物理负责积分与圆形 Trigger 判定；BulletTargetBroadphase 只检查敌弹与少量目标，不枚举敌弹之间的组合。单个测试玩家时，候选检查随子弹数线性增长；多目标会增加 N×T 工作量，实际有效配对还需要稳定排序。

LWPhysicsWorld 增加 Body ID 到槽位的字典索引，消除每颗弹 GetBody／RemoveBody 的线性查找；槽位复用及快照 Restore 会同步维护映射。ProjectileState 复用，活跃列表用末元素交换回收。初次创建状态、集合扩容、Reset／Seek、创建新 Sprite 网格批次仍可能分配内存；零分配结果仅指下述预热后的稳定区间。

表现缓存 Sprite 的真实顶点、UV 和三角形，再合入复用的动态 Mesh。每块最多 16,000 顶点，使用 16 位索引；批次数与 Sprite 种类、每颗 Sprite 顶点数和同屏数量有关。Sprite 相同但颜色不同仍可共用批次。玩家与 Boss 单独使用 SpriteRenderer。

MaxActiveBullets 默认 256，可在 Sequence 中调整；编辑器允许到 16,384。超限会停止模拟并定位来源，不静默丢弹。这个上限是内容保护机制，不能视为已经验证 16,384 弹在手机上满足帧率要求。

## 测试环境与结果

使用 Unity 2022.3.62f1c1 Windows Editor，在临时隔离验证项目中运行相同 Danmaku／轻量物理源码。图形测试启用真实 Unity 图形设备；验证项目使用最小内置渲染环境。当前完整项目的 Assembly-CSharp 与 Assembly-CSharp-Editor 也已依据自身 Unity 引用及编译参数通过 C# 编译。

CPU 模拟测试预先发射指定数量的静止子弹，保留一个固定圆形目标，子弹与目标空间分离；预热 30 Tick，再执行 600 Tick。测量包含轻量物理步进与状态同步，不包含绘制、整个游戏帧、实际密集命中或移动玩家。

| 活跃子弹 | 600 Tick 总耗时 | 平均每 Tick | 测量区间托管分配 |
| --- | ---: | ---: | ---: |
| 100 | 5.36 ms | 0.009 ms | 0 B |
| 1,000 | 54.29 ms | 0.090 ms | 0 B |
| 5,000 | 276.48 ms | 0.461 ms | 0 B |

持续发射／回收测试每 Tick 发射 50 颗、寿命 2 Tick，预热 60 Tick 后再执行 600 Tick，累计生成 33,000 颗；测量区间为 0 B 托管分配，数量与回收断言通过。

Sprite 网格更新测试：1,024 颗相同调试 Sprite 合为一个网格批次，预热后更新 120 次，总计 41.75 ms，平均约 0.348 ms／次，0 B 托管分配。这个时间测量 CPU 网格准备和提交，不是 GPU 完成绘制所需时间，也不代表复杂图集 Sprite 的结果。

原始引擎日志位于 `Logs/DanmakuFinalValidation.log`，检查结果位于 `Logs/DanmakuValidation.txt`；实际引擎渲染图位于 `Logs/DanmakuSpritePreview.png`。Logs 属于本地验证产物，仓库保留本说明中的结果即可。

## 已通过的 12 项检查

1. 八类预设连续步进与 Reset→Seek 的数量、位置、年龄等状态一致。
2. 片段结束帧不多发一轮，结束后已有弹继续存在。
3. 母弹按自身年龄分裂；清弹取消待生成后继。
4. 固定玩家命中走 Enter 去重，Seek 不发布实际命中回调。
5. 复制片段的局部参数独立。
6. 活跃弹上限停止生成并报告错误。
7. 示例资产保存与加载。
8. 物理 ID 索引移除、槽位复用、快照恢复。
9. 100 颗密集弹与一个目标仅检查 100 个候选，无敌弹互查。
10. 100／1,000／5,000 弹稳态模拟与分配检查。
11. 持续发射／回收稳态分配检查。
12. Sprite 网格批绘制、对象数量、顶点块上限和稳态分配检查。

在项目内可通过 `Tools > Danmaku > 运行模拟验证` 或编辑器窗口的“验证”复测。时间轴拖放、窗口布局与 Unity Undo 的具体交互已实现并编译通过，尚未做自动化 UI 操作回归。

## 双端后续验收

接入真实玩家后，选取代表性的持续发射、集中生成、密集命中和分裂爆发样例，在目标手机 Development Build 的 Unity Profiler 中记录逻辑 CPU、渲染 CPU、GPU、GC、批次数和峰值内存。透明像素重叠、大面积弹图与多个 Sprite 批次可能使 GPU 先于碰撞成为瓶颈。

当前离散圆判定没有连续碰撞检测；高速小弹需接入 Sweep 或相对运动扫掠。Seek 从头重演，长符卡与高弹量组合需视实测增加完整模拟快照缓存。当前项目 URP 下的场景显示与 PC／手机 Player 构建尚未做完整平台验收。
