# 自定义歌曲战斗：共鸣舞台策划案

日期：2026-10-13。版本：策划初稿 v1。

2026-10-15 实施更新：首版共鸣舞台已接入，包含歌曲准备、运行时三频分析、确定性弹幕生成、专用战斗场景、重试与独立成绩。已完成 Windows x64 本机运行、原生文件选择器操作、播放设备输出及自动回归验证。接入方式、首版取舍和实测结果见 [实施与复测说明](../../Research/CustomSongBattle/README.md) 与 [验收报告](../../Research/CustomSongBattle/Results/summary.md)。以下保留立项时的现状和策划建议，阅读“当前”“尚未”等表述时以本段实施更新为准。

本文以当前工作区中的代码、场景和配置为依据。文中的现状来自静态核对；新增规则和参数是策划建议，尚未接入运行场景，也未进行本轮实机验收。旧阶段文档与代码不一致时，以当前代码和场景配置为准。

## 1. 定位与核心体验

玩家导入自己的歌曲，设置 BPM 与首拍，进入专用的共鸣舞台。系统依据歌曲的低、中、高频候选点，组合已有弹幕模板。玩家使用现有移动、跳跃、飞行、冲刺和鼠标瞄准射击，在躲避弹幕的同时争取节拍射击奖励，存活到歌曲结束即完成挑战。

一句话体验：**我的歌曲决定 Boss 的出招，我的走位决定能否完成演出，我的节拍射击决定得分。**

Boss 是整首歌曲的攻击源与计分目标。阶段变化由音乐和时间驱动，不要求打掉血量或破坏部位。首版围绕一个固定 Boss 和一个战斗场地制作。

## 2. 当前实现基线

| 模块 | 当前实现 | 对策划的约束 |
| --- | --- | --- |
| 自定义歌曲库 | 主菜单“我的音乐”；MP3/WAV 导入、本地副本、试听、改名、移除 | 沿用这一入口；当前还没有挑战按钮和导入歌曲战斗桥接 |
| 歌曲对齐 | 手动 BPM、首拍秒数、波形点击、进度拖动、节拍器试听、保存 | 首版要求对齐后开始挑战；不宣称自动识别准确 BPM |
| 频段分析 | 编辑器离线分析生成三频候选点及强度 | 可用于攻击编排，但导入歌曲还需要播放器内的分析流程 |
| 实时音乐表现 | 战斗背景频谱曲线、HUD 跳动，共享战斗音乐数据源 | 复用场景表现；实时表现数据尚未驱动 Boss 攻击 |
| 弹幕编排 | 时间轴片段、发射和分裂关键帧、固定随机种子、清弹 | 新生成器输出同一种时间轴，交给既有战斗执行 |
| 攻击模板 | 直线、瞄准扇形、固定扇形、圆环、旋转扫射、墙弹、交错圆环、子母弹 | 首版在这些模板中选取，不依赖激光碰撞、持续追踪等新增类型 |
| 能量球 | 可被玩家弹击碎；膨胀；到分裂点产生子弹；随机区域和出生保护距离 | 可作为高频的互动攻击；具体战斗参数需要新增配置 |
| 玩家 | 左右移动、跳跃、长按飞行、冲刺、技能动作、鼠标瞄准与持续射击 | 当前是有地面和重力的场地，不按任意方向自由飞行编排 |
| Boss | 无血量；启用 BossScoring 后存在计分碰撞目标 | 用持续演出和得分挑战解释战斗，命中不造成 Boss 扣血 |
| 节拍计分 | 命中 Boss 后，按子弹的 FireTick 判断是否在拍点窗口内 | 玩家跟拍开火；不要求按弹道飞行时间提前发射 |
| 连击 | Boss 命中递增；受伤或超过指定拍数没有 Boss 命中则中断 | 能量球击破不延续这条 Boss 计分连击；没有当前连击得分倍率 |
| 结束 | 玩家倒下或歌曲时长到达后结算 | 成功目标是生存到曲终 |
| 战前与结算 | 正式歌曲有装备、评级、成绩和掉落 | 导入歌曲仍需接入身份、启动数据、重试、结算和存档 |

当前 GameplayPlaceholder 场景启用 Boss 计分，配置为普通命中 100 分、节拍额外 50 分、拍点前后各 0.1 秒、连续 2 拍无 Boss 命中断连。当前 MaidGhost 配置为生命 5、体力 100、移速 4、受伤无敌 30 Tick；飞行消耗体力并持续上升，松开后下落。冲刺动作默认禁止开火。

上述数值是现状，并非自定义模式已经调好的平衡参数。当前示例 Sequence 的手动 BPM 为 0，时钟会回退到 60 BPM；自定义模式必须把玩家保存的 BPM 与首拍明确写入本局数据，不能把回退值显示为歌曲的分析结果。

## 3. 入口与场景流程

建议流程：

**主菜单 → 我的音乐 → 选择或导入歌曲 → 设置对齐 → 挑战准备 → 分析与生成 → 共鸣舞台战斗 → 结算 → 再次挑战／返回我的音乐。**

### 3.1 我的音乐与挑战准备

保留现有歌曲列表。在所选歌曲详情增加“进入挑战”按钮：没有音频副本或未保存有效对齐时不可开始，并显示对应处理入口。

挑战准备页展示歌曲名、时长、BPM、首拍、难度，以及“存活到歌曲结束；跟拍开火并命中 Boss 获得额外分数”的说明。

首版预装备已有普通武器，采用固定角色参数，不要求玩家先理解局外装备。已有正式歌曲的武器和道具选择可以作为后续扩展；开启时需明确成绩记录如何区分装备。

生成过程显示“读取歌曲 → 分析频段 → 编排攻击 → 准备舞台”，允许取消并返回。分析成功后显示低、中、高频攻击倾向和预计攻击数；这些是编排结果，不是曲风或乐器识别结果。

### 3.2 专用战斗场景

拟新增独立场景 `Assets/Scenes/CustomSongBattle.unity`，名称为实施建议，目前未创建。入口继续复用主菜单中的“我的音乐”和准备 UI，首版不增加必须行走探索的大厅。

- Boss 位于上方中央，作为持续可瞄准的计分目标。
- 玩家使用当前地面高度、场地尺寸和运动方式。
- Boss 周围增加三个频段标识：低频为粗环，中频为扇叶，高频为小菱形。颜色与形状共同提示攻击类型。
- 复用频谱背景和节拍 HUD。背景强度应低于敌弹和判定圈，避免影响识别。
- 新增歌曲进度与攻击预警；攻击预警和射击节拍提示位置分开。
- 暂停、失焦、音乐与逻辑同步沿用当前战斗流程。

开场倒数作为新增准备环节：倒数结束后同时开始音乐和本局时间。不要在倒数期间默默播放歌曲。首拍前可以瞄准和移动，首版不安排强攻击。

## 4. 高频、中频、低频的攻击分工

设计重点是“同一套操作，应对不同频段的空间压力”。所有攻击都由现有圆形子弹和关键帧构成。

| 频段 | 攻击名称与模板 | 玩家应对 | 音乐表现 |
| --- | --- | --- | --- |
| 低频 40–250 Hz | 重音扩散：圆环、交错圆环；后续可加稀疏墙弹 | 提前横移，选择落地路线，必要时跳跃或冲刺穿越 | 粗环收缩蓄势，低频候选点处扩散 |
| 中频 250–2000 Hz | 旋律追射：瞄准扇形；稳定段落使用旋转扫射 | 引导瞄准方向后移动，沿扇形或旋转弹缝调整位置 | 扇叶转向，发射时展开 |
| 高频 2000–10000 Hz | 晶音弹群：小规模固定扇形；较强候选点可生成可击碎能量球 | 小幅走位；选择继续射 Boss 保分或转火能量球减压 | 小菱形闪烁，能量球逐渐膨胀 |

### 4.1 低频：重音扩散

普通攻击从 Boss 附近发射一圈较慢的大视觉弹。重音较强时在数量或交错角度中选择一项加强，速度维持可预判。

首版建议每轮 8–12 弹，速度 1.5–2.0 世界单位／秒，寿命 3–4 秒；均为起始调参范围。弹体大小与判定半径分别配置。不能用视觉大幅膨胀掩盖实际判定，也不能把“大弹”解释为多点伤害；当前有效受伤固定为 1。

若加入低位横向弹，必须保留地面移动或跳跃路线，不能要求每次低频出现都必须消耗体力飞行。一般候选点之间也不应连续制造覆盖全部落地点的墙弹。

### 4.2 中频：旋律追射

主要使用 3–5 发瞄准扇形，建议扇角 35–60 度、速度 2.0–2.8 世界单位／秒。瞄准在每次发射时采样，发射后沿固定方向前进。

连续攻击采取“发射 → 等待 → 再次瞄准”，不给同一位置连续堆叠无间隔弹群。旋转扫射采用少量发射方向和有限持续时间，不直接扩大为全屏高速螺旋。

预警可以提示即将瞄准发射。若要展示精确轨迹，则必须让预警与实际锁定方向一致；当前没有提前锁定方向的独立机制，首版不要承诺一条固定预警线后在发射时重新瞄准。

### 4.3 高频：晶音弹群与能量球

弱候选点使用少量固定扇形弹，建议每轮 3–5 发，避免将每一次镲片变化都转换为高速弹雨。

强候选点可以选择能量球攻击：母球出现并膨胀，玩家在分裂前击碎则消除该球的后续弹幕；未击碎则释放小型圆环。首版最多同时一个母球，建议分裂前留出至少 4 拍且不少于 1.5 秒，爆炸环初始 6–8 弹。

首版母球建议不造成接触伤害，出生位置选在上方的有限区域，避开玩家和主要落地区。击碎后的奖励先沿用已有能量球计分配置，不赋予它未实现的节拍 Perfect 奖励。

这会形成现有系统支持的取舍：继续瞄准 Boss 能保持命中与连击；转火母球能够减少未来压力，但若连续 2 拍没有 Boss 命中，Boss 计分连击仍会中断。普通难度不让能量球成为必须击碎才能生存的目标。

当前时序在分裂 Tick 先执行爆炸，再处理当 Tick 玩家弹碰撞，因此成功阻止爆炸必须早于分裂 Tick。提示应表达“爆炸前击碎”，不能宣称爆炸同 Tick 命中一定能取消攻击。

## 5. 自动编排规则

生成路线采用**战前分析整曲并生成现有 Sequence**，随后由当前 BossSequenceRunner 执行。这样可以提前预警、复用时间同步和弹幕编辑器，并让重试保持相同攻击安排。

候选点是频段起音提示；手动 BPM 与首拍提供计分拍点。两种数据用途不同，不把所有频段候选点当作 BPM 拍点。

### 5.1 选择攻击

1. 三频分别过滤与归一化候选强度，避免某个频段因天然能量更大而长期占满攻击名额。
2. 将手动拍网格按每 4 拍划分为编排单元。这只是游戏调度单位，不宣称识别了歌曲真实小节或拍号。
3. 在每个单元内挑选有代表性的候选点，按频段映射模板。首版尽量保持所选候选点原始时间，不将所有声音强制移到整拍。
4. 同时或很接近的候选点合并决策：选择一种主攻击，允许较轻的辅助攻击；超过密度预算则跳过。
5. 攻击类型变化不改变 Boss 计分窗口。玩家仍按保存的拍网格开火。

### 5.2 限制密度

首版调参建议：

| 规则 | 普通 | 困难（后续开放） |
| --- | --- | --- |
| 主要攻击间隔 | 至少 2 拍，且不少于 0.75 秒 | 至少 1 拍，且不少于 0.5 秒 |
| 重攻击预警 | 至少 1 拍，且不少于 0.5 秒 | 至少 1 拍，且不少于 0.35 秒 |
| 同时活跃攻击结构 | 1 种主结构，少量辅助弹 | 最多 2 种结构 |
| 能量球数量 | 同时最多 1 个 | 调参后决定是否增加 |
| 弹幕预算 | 先从约 120 个同时活跃敌弹开始校验 | 另行校验，不直接按歌曲响度放大 |

预警在候选点之前，弹幕生成在候选点处。这里同步的是发射与音乐，不宣称子弹到达玩家位置时恰好落拍。

总容量校验必须计入玩家弹、母球和分裂子弹。当前 BattleConfig 实战容量为 2048，超限会产生 Fault 并暂停，不能将容量上限当成自动降级机制。生成时根据寿命、发射数和分裂数预留空间；预计超预算时主动减少或跳过攻击。

### 5.3 场地公平性

- 普通难度必须有适合当前横移、跳跃和下落运动的可行路线。
- 避免同一时间把地面、上升区域和落地区全部封死；不要求无限飞行。
- 每若干编排单元安排压力回落，给玩家落地和体力恢复机会。
- 所有重攻击都采用明确预警。现有时间轴有 Warning 数据，但当前实战缺少相应攻击预警表现，需要新增显示接入。
- 不在玩家附近即时生成危险弹；随机区域必须结合保护距离校验。
- 不把子弹数量、速度、尺寸和寿命同时随强度上调。

固定随机种子与片段稳定 ID 由歌曲内容 ID、难度和生成规则版本确定。同一配置重试得到相同基础谱面；瞄准弹和出生保护仍可能因玩家走位产生不同轨迹或位置。

## 6. 演出起伏

首版不依赖自动主歌／副歌识别。先采用固定流程和候选活动度调节：

- 开场前 8 拍：稀疏展示三频攻击，较短歌曲相应缩短。
- 常规演奏：单一主结构为主，随候选点改变攻击类型。
- 活跃段：候选较密集时允许辅助攻击，但始终遵守难度预算。
- 恢复段：隔若干编排单元降低生成密度，并在音乐较弱时优先安排。
- 收尾最后 8 拍：不再生成来不及完成的新能量球，逐步减压；歌曲结束立即按已有规则结算。

需要从候选点数量和强度推导活动度时，将它称为“攻击活跃度”。当前分析结果不是已经实现的离线持续响度包络，也不是歌曲段落识别结果。

## 7. 得分与结算

首版保留现有普通命中、节拍奖励、受伤断连和命中超时断连。说明文案为：“在节拍点开火，并让子弹命中 Boss，可获得节拍奖励。”

当前 Boss 计分部分为：

`Boss 命中数 × 100 + 节拍命中数 × 50`

其他分数项取决于已有 ScoreFormula 配置。当前连击不直接提供额外倍率；不要在界面上展示未实现的倍率奖励。

结算展示：歌曲是否完成、总分、Boss 命中数、节拍命中数、最高连击、受伤次数、能量球击破数。可以新增“节拍奖励命中占比 = 节拍命中数 / Boss 命中数”，它是命中子弹中获得节拍奖励的比例，不是全部拍点的完成准确率。无 Boss 命中时显示“暂无”。

自定义歌曲的最高分按歌曲内容 ID、难度、生成规则版本记录；若以后开放武器和装备，再明确记录所用配置。长歌曲与不同射速天然影响总分，首版不比较跨歌曲总分，不直接套用正式歌曲的绝对 S/A/B 阈值。

首版建议用“完成／未完成 + 最高分”作为成绩展示，评级后续校准。自定义模式先不发放局外道具，避免任意时长歌曲改变已有奖励节奏；这需要自定义结果分支，当前正式流程会校验掉落表并进行掉落，不能仅隐藏掉落文本。

结算提供“再次挑战”和“返回我的音乐”。重试保留歌曲、对齐、难度与谱面版本；返回时选中刚刚挑战的歌曲。首次最高分、新纪录和保存失败重试沿用当前存档交互风格。

## 8. 需要新增的连接与内容

| 工作 | 可复用部分 | 必须新增部分 |
| --- | --- | --- |
| 自定义挑战入口 | ImportedMusicView、AudioAlignmentView | 挑战按钮、准备页、有效对齐检查、返回上下文 |
| 播放器内三频分析 | 现有纯算法与分析数据结构 | 当前分析器位于 Editor 目录；需提取共享算法并接入运行时读取、进度、取消、缓存 |
| 谱面生成 | DanmakuSequence、DanmakuClip、EmissionPreset | 三频选点、模板映射、密度与容量预算、稳定种子及 ID |
| 启动与场景切换 | BattleManager、SceneFlowService、Loading | 自定义本局数据、专用关卡入口、运行时音频和 Sequence 生命周期 |
| 战前选项 | 已有角色与普通武器 | 固定配置准备入口；后续再接装备 |
| 预警和频段提示 | Warning 数据、节拍 HUD、频谱背景 | 实战消费攻击预警、三频标识、歌曲进度 |
| 自定义结算 | ScoreManager、BattleStats、保存重试模式 | 导入歌曲标题来源、自定义记录键、无掉落分支、返回歌曲库 |

当前 BattleStartData.Validate 要求 SongDefinition 属于正式 SongCatalog，ResultView 也从正式目录查标题，LoadoutView 从正式选曲页取所选歌曲。导入歌曲不能只替换一个 AudioClip 就完成全流程；上述连接属于首版必要工作。

生成的本局数据不修改已有正式歌曲模板。首次分析成功后按音频内容与分析设置缓存；对齐改变时重新编排，难度或生成规则版本改变时生成对应谱面。重播与离开时正确释放本局音频和临时数据。

## 9. 首版范围与验收

首版交付：一个自定义战斗场景；一个 Boss；普通难度；固定普通武器与当前角色；低频圆环、中频瞄准扇形、高频小扇形及少量能量球；导入、对齐、生成、开战、暂停、曲终／死亡结算、重试与返回形成闭环。

暂后置的扩展：多 Boss、部位破坏、激光、持续追踪、自动变速 BPM、段落语义识别、跨歌曲排行榜、装备构筑与新的节拍倍率。技能沿用已有动作；首版弹幕不要求某个技能一定已准备好才能通过。

策划验收重点：

1. 选择至少三首不同频谱和节奏的歌曲，能够看出攻击结构差异，而不只是颜色差异。
2. 高频丰富歌曲受到密度限制，低频稀少歌曲仍有清晰但较轻的挑战，静音区不会突然补发大量攻击。
3. 跟拍发射并命中 Boss 能得到额外奖励，距离变化不改变发射拍点判定；普通命中仍计分。
4. 玩家在地面、跳跃、飞行和下落状态都有可解释的路线，恢复段能补充体力。
5. 能量球在爆炸前击碎可阻止分裂；普通难度漏球后仍有躲避机会。
6. 同一歌曲、对齐、难度及版本重试，基础编排相同；暂停恢复不重复发射或错过预警。
7. 歌曲结束或生命耗尽只结算一次，最高分正确保存，返回后仍能找到该歌曲。
8. 未对齐、音频缺失、分析取消、生成失败、超预算和存档失败都有对应可恢复路径。

## 10. 同框架下的两个备选主题

| 主题 | 主要区别 | 对现有实现的适配 |
| --- | --- | --- |
| 黑胶回响 | Boss 外观为唱片；低频圆环、中频旋转扫射、高频能量球 | 同样使用无血量计分 Boss，偏重旋转弹幕与视觉主题 |
| 乐队试演 | 低、中、高频分别由三个舞台音箱发射 | 复用片段独立发射器；首版三个音箱仅是发射与表现节点，不宣称有独立血量或可破坏部位 |

推荐共鸣舞台作为首版，因为它同时展示当前已有的节拍计分、三频表现、移动动作、弹幕预设和能量球交互。
