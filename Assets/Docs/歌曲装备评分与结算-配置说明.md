# 歌曲、装备、评分与结算配置

## 使用入口

打开 `Assets/Scenes/Title.unity` 并进入 Play 模式。

- **开始游戏**：已有游戏存档时先确认，再清空歌曲成绩及道具获取数量。个人设置保留。
- **继续游戏**：保留成绩及道具，进入歌曲选择。不恢复任何局内战斗状态。
- 歌曲选择 → 装备选择 → 加载 → 战斗 → 结算。
- 结算重试：沿用歌曲、难度、弹幕和装备，重新初始化全部战斗状态。
- 结算下一步：返回 Title。
- 暂停退出：放弃当前战斗并返回 Title，保留永久存档。暂停菜单不提供保存按钮。

## 配置入口

`Assets/Configs/Spotlight/SystemConfig.asset` 持有：

| 字段 | 用途 |
|---|---|
| Songs | 歌曲目录 SO，数组顺序决定列表顺序 |
| Weapons | 允许选择的玩家武器 SO；目前支持 Normal、Spread |
| Items | 可获得、可装备道具目录 |
| Item Slot Count | 道具槽数量，默认 3 |
| Drops | 结算掉落表 SO |
| Score Formulas | 多个评分公式 SO，各分数项相加 |

首批示例资产在 `Assets/Configs/Spotlight/Run/`。只绑定项目现有的正式战斗曲目；Normal 开放，Hard、Expert 默认关闭，避免没有对应关卡资源的难度被启动。打开难度前应配置对应 Battle 和 Rating。

新增歌曲通过 Create → Spotlight → Song / Song Catalog。每个 Song 的 Id 必须唯一且保持稳定。歌曲包含名称、副标题、作者、封面及各难度配置。每个难度的 Enabled 控制按钮是否置灰；Battle 指定战斗配置；Rating 指定评级 SO；Level Entry Id 对应已有 LevelEntryCatalog 中的场景入口。

多首歌可以使用同一战斗场景，加载后由 BattleStartData 注入对应 BattleConfig。BattleStartData 是内存中的“本局开局配置”，记录歌曲、难度、玩家弹幕和装备，重试沿用它。

## 战斗结束与统计

- DanmakuSequence.DurationTicks 是弹幕时间轴结束点，60 Tick = 1 秒。有音乐时本局以歌曲实际结束时间（含音乐开始偏移）结算，无音乐时以时间轴结束结算。
- 歌曲完成和角色倒下均进入同一歌曲结算页面，显示对应结束原因；统计、存档及道具奖励只执行一次。
- Boss 无血量、无受伤与死亡判定，玩家子弹穿过 Boss。所有有效弹幕伤害固定为 1，普通子弹命中一次后消失，击碎能量球后也不穿透。道具 Buff 支持移动速度、射速及子弹速度，不提供伤害加成。
- 击破能量球增加连击，记录最大连击。
- 未击破能量球到期、离场或到达母球分裂/爆炸期限时记 MISS 并断连。
- 关卡清弹、停止战斗和结算清理不计 MISS。
- 玩家有效受伤单独记录次数与伤害量，不计 MISS。

## 评分 SO

Create → Spotlight → Scoring 可创建公式资产。

默认占位公式：

| 公式 | 默认参数 |
|---|---|
| Orb Score | 每个击破能量球 +100 |
| Max Combo Bonus | 最高连击 ×10 |
| Miss Penalty | 每次 MISS -50 |
| Completion Bonus | 通关 +1000，失败 +0 |

分数管理器在结束时把 BattleStats 传给每个 ScoreFormula，求和并将总分限制为不低于 0。重复 SO 引用会重复计分，因此需要注意列表配置。

评级使用独立 ThresholdRatingFormula，按最高满足的分数阈值确定等级，列表无需排序。示例阈值 C=0、B=2000、A=5000、S=10000、SS=20000，均为占位值，可为不同歌曲、难度创建不同评级资产。

自定义公式：继承 ScoreFormula，重写 `int Evaluate(BattleStats stats)`。自定义评级：继承 RatingFormula，重写 `RatingValue Evaluate(int score, BattleStats stats)`。新 SO 类放在同名 .cs 文件中，通过 CreateAssetMenu 创建资产并拖入配置。

## 道具与 Buff

ItemDefinition 配置唯一 Id、显示名称、说明、图标、主动/被动、单局携带上限 MaxHeldPerRun、每局使用次数、冷却 Tick 及 ItemEffect。实际单局可用次数取库存数量、携带上限、每局使用上限的最小值。准备界面的布局、单击/双击规则及 CSV 文案配置见 [开始前准备界面与普通道具-配置说明](开始前准备界面与普通道具-配置说明.md)。

- 永久获取数量大于 0 才能装备；同一道具不重复占槽。
- 主动道具通过现有 Tab/数字键选择、R 使用，实际键位以设置为准。
- 按下 R 时绑定具体道具，在下一个战斗 Tick 开始时执行；角色存活时不受当前动作窗口限制，也不打断动作。效果成功才扣局内次数，失败提示原因。
- 被动道具开局应用效果。
- 每次重试恢复局内次数，不扣永久获取数量。
- 当前仅保留回血 2 点、5 秒弹幕爆发两种主动道具；四个占位道具已从目录、掉落及资源中移除。

可用 Create → Spotlight → Items → Buff Effect 创建真实 Buff 效果，或继承 ItemEffect 编写新效果。

BuffManager 支持 MoveSpeed、FireRate、ProjectileSpeed、ProjectileCount。计算规则为 `(基础值 + 固定加成之和) × 倍率之积`，有效移速和弹速限制为非负，射速限制为每秒 0.001–60 轮，每轮弹幕数量限制为 1–64 枚。

Buff 用 Tick 计时，暂停不推进。DurationTicks=0 持续整局；MaxStacks 控制叠层上限，达到上限时替换最早的一层。普通移速与动作自身 MotionScale 组合，冲刺速度继续由动作配置决定。道具先于当 Tick 的属性读取和碰撞结算，射击增益当 Tick 生效；不修改基础配置资源。

## 掉落与存档

ItemDropTable 的 Entries 配置 Item、Weight、Quantity。每次成功或失败结算都按权重抽取一个条目，发放该条目的数量，允许重复获得。空表、无效条目和不在 Items 目录中的道具会阻止启动。

永久游戏存档是 `Application.persistentDataPath/Spotlight/game.json`（目录可由 SaveFolder 调整），同时保存歌曲/难度的最高分、对应评级、道具获取数量和最近一次结算 ID。个人设置仍在独立的 settings.json。

失败局允许刷新最高分；同分保留原记录。成绩与掉落一起写入，重复打开结算和重复保存不再掉落。写入失败时显示重试保存，沿用同一次抽取结果，保存成功后再重试或返回。旧 progress.json 的局外养成数据不作为新的歌曲存档读取。

## 编辑器工具与验证

- Tools → Spotlight → 接入歌曲装备与结算：增量创建缺失配置和三个面板，不重建已有场景；已有新面板保留手工编辑。
- Tools → Spotlight → 验证歌曲装备与结算：运行统计、存档、Buff、掉落、生命周期和引用验证，结果在 Logs/SpotlightRunValidation.txt。
- PlayMode 的 Spotlight.Tests.SystemFlowTests 验证 Title、难度禁用、装备、加载、暂停、通关/失败结算、掉落去重、重试、继续和新游戏重置。

示例图标、道具效果和评分参数是可替换配置；跟踪武器尚未实现，按钮保持不可选。
