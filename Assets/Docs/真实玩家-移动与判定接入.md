# 真实玩家：第 2–4 步接入

第 2 步建立输入 Tick 缓冲和定点移动；第 3 步让轻量物理的玩家目标逐 Tick 更新；第 4 步将玩家属性移到独立 SO。玩家和子弹使用 DanmakuSequencePlayer 内部同一个 60 Hz 时钟。

## 场景挂载

1. 在独立的 `DanmakuRoot` 上挂 `DanmakuSequencePlayer`，指定 Sequence。场地根节点推荐位置／旋转为零、缩放为一，保持稳定。
2. 玩家对象上挂 `PlayerInput`、`Inputs.PlayerInputManager` 和 `PlayerInputSampler`。PlayerInput 的 Actions 指向 `Assets/Inputs/DanmakuControls.inputactions`，Default Map 为 `Gameplay`。
3. 将采样器拖到播放器的 Input Source；将 `Assets/Inputs/DefaultPlayer.asset` 拖到 Player Config。
4. Player Spawn Position 是真实玩家的场地局部出生位置，默认 `(0,-4)`。Player Visual Root 指向玩家对象；留空时使用 Input Source 所在对象。该对象不能是 DanmakuRoot 或其祖先。
5. Player Sprite Renderer 可以指定玩家的 SpriteRenderer，推荐放在玩家对象的 Visual 子节点。留空会尝试读取 Player Visual Root 自身的 SpriteRenderer。配置中有 Sprite 时，Play 会应用 Sprite 和 VisualSize；配置中没有 Sprite 时保留场景原有表现。默认玩家配置使用示例圆形 Sprite。
6. 在弹幕编辑器中，把同一份 DefaultPlayer 指定为 Sequence 的“预览玩家配置”。“测试玩家位置”只用于编辑器；实时模式不会读取它作为出生位置。

Input Source 为空时继续使用原来的固定测试模式。实时模式的 Sprite 批绘制不会再额外生成测试玩家和 Boss 标记；玩家表现来自场景对象，Boss 表现由实际场景负责。

## 配置所有权

`DanmakuPlayerConfig` 保存 NormalMoveSpeed、FocusMoveSpeed、HitRadius、Sprite 和 VisualSize。默认普通速度 4 世界单位／秒，低速 1.8，判定半径 0.08。Focus 改变速度，不改变判定半径。HitRadius 与 VisualSize 独立。

`DanmakuSequence` 保存场地与攻击时间轴、PreviewPlayerPosition 和 PreviewPlayerConfig。CollisionEnabled 是固定预览模式的碰撞开关；实时玩家的碰撞开关来自 DanmakuPlayerMotor.State。

旧资产中的 PlayerPosition 会迁移到 PreviewPlayerPosition；旧 PlayerHitRadius 和 PlayerSprite 迁移到隐藏兼容字段。没有 PreviewPlayerConfig 的旧资产仍可预览，指定新配置后使用配置中的半径和 Sprite。兼容性已用 Unity 生成的旧字段资产重导入检查。

运行时 SO 是模板。Play 时把速度／半径编译成 FP64，新攻击会重新读取配置；运行中修改 SO 不会立即改变已创建的 Motor。切换攻击时保留现有定点位置和碰撞开关，按新场地边界限制位置。ResetPlayer 可显式回到 Player Spawn Position。

## 每帧与每 Tick 的执行顺序

每个渲染帧，播放器先调用 PlayerInputSampler.Capture，读取当前 Move／Focus／Fire。Move 的浮点轴量化为 -32767～32767 的整数；移动计算通过 InputSnapshot.Move 转为 FP64。

Bomb／Pause 的 performed 事件进入 InputTickBuffer。没有 Tick 的渲染帧保留按键；每次 ConsumeTick 消耗一次按键，多个 Tick 不会重复同一次按键。多次按键可在后续 Tick 中逐次消费。Action Map 切换、输入禁用和暂停／恢复会清理过期的按钮输入。

时间累加器把渲染帧时间换成整数逻辑步。每个 Tick 依次执行：

```csharp
InputSnapshot input = inputSource.ConsumeTick();
playerMotor.Step(input);
simulation.SetPlayerState(playerMotor.State);
simulation.Step();
OnInputTick?.Invoke(input);
```

Motor 使用 `位移 = 输入方向 × 当前速度 × 1/60`。输入长度超过 1 时归一化，防止斜向移动加速；低于 1 时保留摇杆强度。中心限制在 `[-FieldSize/2 + HitRadius, FieldSize/2 - HitRadius]`，不让判定圆越过场地边界。玩家移动只由 Motor 负责，不会被 LWPhysicsWorld 再积分一次。

SetPlayerState 同时更新自机狙采样位置、LWBody.Position、圆形 Shape.Radius 和碰撞 Mask。PlayerState 是这几个消费者的共同真源。命中事件额外携带 PlayerPosition 和 PlayerHitRadius，记录触发判定时的状态。

所有 Tick 执行完后，播放器将逻辑位置通过场地根节点 TransformPoint 转成玩家表现的世界位置，再提交子弹网格。当前玩家和子弹都显示最后完成 Tick 的位置，尚未加入渲染插值和 Focus 判定圈特效。

## 运行时控制与接口

- Pause／Resume 同时暂停和恢复玩家与子弹，不累积暂停期间的补跑时间，并丢弃暂停期间的 Bomb／Pause 输入。
- 实时模式中，攻击结束后玩家仍可移动。Simulation.Finished 用于判断攻击完成；Playing 表示公共时钟仍在运行。固定测试模式的攻击结束仍会停止播放。
- Loop 重置攻击与随机流，保留真实玩家位置。
- 切换 Sequence 后调用 Play 可开始下一段攻击；玩家位置保留。跨攻击场地大小变化可能造成边界钳制。
- `PlayerMotor.SetCollisionEnabled(false)` 可关闭玩家命中判定；下一 Tick 同步到物理世界。真正的受击无敌、扣血、Buff 与 HitCount 策略在后续战斗层接入。
- `OnInputTick` 每完成一个玩家 Tick 发布一次 InputSnapshot。FireHeld／BombPressed／PausePressed 已可供业务消费；当前尚未自动射击、释放符卡或打开暂停 UI。例如菜单控制器可以在 PausePressed 时调用 Pause，关闭菜单时调用 Resume。
- 实时模式暂不支持 Seek，因为重演移动目标需要输入记录；固定编辑器预览的 Seek 保持可用。PreviousPosition 已保留，后续相对连续碰撞检测可以使用。
- AdvanceFrame 通常由组件 Update 自动调用；它也用于受控验证，实际运行时不要再从另一个 Update 重复调用。

## 验证

`Tools > Danmaku > 运行玩家移动与判定验证` 包含按键跨帧消费、普通／低速／斜向／摇杆移动、半径边界、30／60／144 FPS 的固定 Tick 一致性、当 Tick 自机狙、动态目标判定、暂停恢复、旧资产迁移与稳定期分配检查。报告输出到 Logs/DanmakuPlayerValidation.txt。

本次还在隔离的 Unity 2022.3 项目中进行原生 Play 模式集成验证：使用真实 PlayerInput、输入资产和注入的 Keyboard 事件，检查玩家移动、局部／世界坐标转换、Bomb 跨帧缓冲、攻击结束后的移动、暂停恢复、Gameplay／UI 切换及跨攻击位置保留。报告位于 Logs/PlayerIntegrationValidation.txt。批处理没有 Game View 焦点，验证夹具单独设置为允许游戏读取输入；主项目的输入设置未改动。

固定 Tick 一致性指相同 InputSnapshot 流产生相同结果；真实设备在不同帧率下的输入事件采样时机仍受输入系统更新影响。当前没有玩家输入回放记录。

高速弹和快速玩家位移仍使用离散圆形重叠检查；渲染插值、判定圈视觉、Damage／Buff 和相对 Sweep 属于后续步骤。PC／手机整帧性能还需要目标设备实测。
