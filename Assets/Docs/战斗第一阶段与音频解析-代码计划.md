**战斗第一阶段与音频解析：代码计划**

状态：原始代码计划。用户已授权直接实施，并明确无需旧资产兼容；实际实现、确认的场景/歌曲和验收操作见 [战斗第一阶段与音频解析-接入说明](战斗第一阶段与音频解析-接入说明.md)。适用项目：Unity 2022.3.62f1c1。

依据：聚光灯-弹幕需求新增.pdf、当前 Danmaku Runtime/Editor、Inputs、System 音量及暂停代码。

**一、交付范围**

本轮完成两条功能链：

1. 第一阶段战斗：角色移动、鼠标瞄准、左键持续射击、常规和散射武器、Boss 受伤、敌弹伤害玩家、统一碰撞结算、暂停恢复、共享弹幕模拟和批绘制。
2. 音频：Sequence 选择 AudioClip、离线解析、音乐波形轨道、低/中/高频节拍候选点、播放与拖动试听、标记吸附、编辑器和运行时使用相同时间映射及解析资产。

后续阶段实现能量球击碎与连击、弹反、持续跟踪运动、五档弹反难度，以及跳跃/飞行的具体判定。第一阶段保留相关扩展边界，避免提前实现未定玩法。

已经确认：跟踪弹优先 Boss；能量球由玩家主动瞄准射击。后续跟踪弹的目标选择不能默认抢锁能量球。

数值表定义常规 10 伤害、5 次/秒、1 弹；散射 5 伤害、2.5 次/秒、5 弹；跟踪 4 伤害、8 次/秒、1 弹。跟踪模板可以保存，但本轮不把直线弹当作完成的跟踪武器提供。弹速、扇形角度等未给定精确值的字段支持配置，示例值标为暂定。

音乐开启时第一版统一 1 倍速，编辑器和运行时同步限制；保留无音乐模式的现有倍速。变速不变调、复杂节拍/小节识别以及自动生成完整 Boss 攻击编排不在本轮。解析得到的是分频起音/节奏候选点，供设计人员编排，不能宣称是精确 BPM 或小节线。

**二、现有代码的关键改造**

- DanmakuSimulation 同时负责时间轴、子弹世界和面向玩家的命中。拆出 BossSequenceRunner 和 ProjectileWorld，保留 DanmakuSimulation 作为旧固定预览接口的包装，包装本身不再保存另一份子弹世界。
- Sequence.DurationTicks 只控制该攻击段的发射调度。战斗世界在攻击段结束后继续移动残留弹和角色弹；战斗结束由 BattleSimulation 判断。
- Sequence.ClearAtEnd 只清该攻击段来源的敌方弹及待生成请求，不清角色弹。旧固定预览仍保留原先停止/Seek 的语义。
- 当前 ProjectileHit 面向玩家，新增通用 CombatContact 和 BattleEvent。扣血与子弹命中次数消耗在战斗 Tick 内完成，事件在提交状态后发布。
- BulletTargetBroadphase 扩展为双向阵营与目标类别筛选，第一阶段仅需要 PlayerProjectile→Boss、EnemyProjectile→Player。不开启全部子弹互撞。
- SpritePool/Batch 继续共享，改为读取 ProjectileWorld 的只读子弹状态；兼容旧预览包装。每颗弹仍无独立 GameObject。
- 现有 PlayerInputSampler 采集移动及 Fire；增加战斗坐标中的瞄准数据和左键绑定。技能输入统一到战斗输入入口，第一阶段不执行弹反。
- 现有 SpotlightAudioSource/AudioVolumeService 用于注册实战音乐音量，不引入另一套全局音量设置。

**五、战斗数据与规则**

阵营保存于运行状态，来源保存完整身份：SourceKind、OwnerId、SequenceInstanceId、ClipId。不要仅用 SourceClip=-1 表示所有角色来源。

伤害使用 FP64。角色/Boss 生命也使用同一数值体系。DamageConfigId 保留为配置查询入口；定义唯一解析函数，明确使用显式伤害还是 ID 配置，禁止两者叠加。当前项目无实际伤害配置服务，本轮提供显式配置路径和扩展接口。

第一阶段规则：

| 双方 | 结果 |
| --- | --- |
| 玩家弹与 Boss | Boss 可受伤则扣生命，消耗该弹 RemainingHits；达到零时标记移除 |
| 敌弹与玩家 | 玩家可受伤则扣生命，消耗该弹 RemainingHits；达到零时标记移除 |
| 玩家弹与普通敌弹 | 无交互，筛选阶段不生成候选对 |
| 同阵营弹与角色 | 无交互 |

ActorState 包含 IsAlive、CanReceiveDamage 和可配置的受伤无敌 Tick。无敌期间弹是否消耗写为明确策略字段，示例采用命中接触消耗弹、免除生命损失，不能靠回调顺序决定。

ActorId/ProjectileId 与物理 BodyId 建立映射。对象池复用不允许残留旧 Tick 的引用生效；每 Tick 事件保存值快照，外部不得保留可回收 ProjectileState 作为结果。

射击初次按下允许立即发射；之后保留间隔余量。松开时不会存储无限发射债务。鼠标与枪口重合时保持上次有效方向。Aim 在渲染帧采样、量化为战斗平面定点数据，每 Tick 使用已采样快照，模拟内不访问 Camera/Mouse。

战斗本 Tick 顺序：消费输入 → 移动与受伤状态 → 同步 Actor 物理体 → Boss/角色发射 → 物理推进与接触 → CombatResolver → 存活弹的寿命/分裂 → 提交回收与结果 → 视图同步。

快速角色弹加入针对圆形目标的扫掠检测，使用双方相对移动路径；与离散 Trigger 结果合并去重，每对同 Tick 最多处理一次。必须同步扩展扫掠候选筛选，不能只对帧末重叠候选执行路径检测。

编辑器固定预览和实战空输入模式复用同一核心。随机流继续由 Sequence 种子与稳定 ClipId 决定。多人/多 Boss 架构不在本轮，但接口避免写死 playerId。

**六、音频解析数据与算法**

新增分析资产不修改源音频数据。Sequence 持有源 AudioClip 和分析资产引用；可以多段攻击共享一首歌的分析结果。

MusicAnalysisAsset 保存：

- 源 AudioClip 引用、GUID/依赖指纹、导入设置指纹、分析器版本、参数指纹。
- SampleRate、Channels、SampleFrameCount、Duration。
- 波形 min/max 摘要，按有限分辨率分桶，长歌不保存原始 PCM。
- 标记数组：SampleFrame、BandId、Strength。保留原始采样位置，不在资产中提前折损为 60Hz Tick。
- 分频范围、FFT 窗口、Hop、阈值、最小间隔与时间补偿参数。

建议初版算法：

1. 主线程分块读取交错 PCM，校验 GetData 返回值与加载状态，尾块不允许越界回绕污染分析。
2. 多声道分别计算频谱并合并能量，避免简单左右相加使反相信号抵消。
3. Hann 窗 + FFT，默认窗口 2048、Hop 512，参数可配置。
4. 低频 40–250Hz、中频 250–2000Hz、高频 2000–10000Hz，按实际 Nyquist 上限截断。
5. 每频段计算能量和正向频谱变化，用局部自适应阈值、局部峰值和最小间隔提取候选。
6. 计算并记录窗中心/起音补偿；静音不生成候选，尾部补零只为 FFT，不能生成 clip 之外标记。
7. 保存排序后的标记与波形摘要，更新分析参数和缓存指纹。

全曲读取和 FFT 分块推进，提供进度、取消、明确失败原因。纯数值计算可移到后台，但不得在后台调用 AudioClip、AssetDatabase 或 Unity GUI。取消/失败保留旧分析结果，只在成功后替换资产内容。

AudioClip.GetData 不能读取 Streaming 音频；压缩音频读取要求 Decompress On Load。主方案用编辑器临时分析副本，设置可读 PCM 并分析，完成后清理副本；源资产 GUID、导入设置和运行时 Streaming 策略保持原样。副本重导入、重采样和清理必须在实现前段验证，并保存实际分析采样率及帧数。分析不适用的资源类型报告具体限制，不能把零数组当成功。

不增加实时 FFT 或运行时重新解析；不把候选点自动写成技能。设计人员可选择标记，将片段开始位置吸附到最近的同频段标记。重新解析不移动现有片段和事件。

**七、编辑器 UI 与播放同步**

在现有时间轴顶部增加音乐行、波形以及三个频段标记行。共享横向滚动、缩放与游标，不生成独立不对齐的时间轴。

功能包括：AudioClip 选择、解析/取消、分析参数、缓存是否过期、频段筛选、标记强度提示、吸附开关、播放/暂停、拖动定位。绘制只扫描可见范围，候选密集时按屏幕像素聚合，保留资产原始标记。

音乐起始偏移定义：MusicStartSeconds>0 表示音乐在战斗开始后延迟该秒数播放。标记在战斗中的时间为 SampleFrame/SampleRate + MusicStartSeconds；播放位置反向换算。负偏移表示开场从歌曲中段播放。映射函数在 Runtime 中共用，编辑器不能另写一套。

已有片段 StartTick/DurationTicks 保持 60Hz。标记吸附转换到最近 Tick，并显示量化误差；相同 Tick 的多频段标记仍保留。Tick 表示已完成的 Step 数，Step 执行 [Tick, Tick+1)，兼容当前 Seek(0) 尚未发射的语义，验证时要计入这一 Tick 边界。

运行时后端使用 AudioSource.PlayScheduled 和 DSP 起点；transport 从共享样本/DSP 锚点计算战斗目标完成 Tick，由宿主按序补齐逻辑步，不能跳过模拟步骤。无音乐时继续使用现有固定累加时钟。两个模式同一时刻只能启用一个时间源。

正常小幅落后执行固定步补齐；严重落后且超过补步预算时，暂停音频和推进、恢复匹配位置后重建起点，记录同步失败原因；不能让音乐无限向前而逻辑永久滞后。播放开始前的调度准备时间不计入战斗时间。

暂停保存歌曲位置与战斗状态；恢复重建映射，不补跑暂停时间。Seek 时先暂停试听、静默重演固定预览，再将歌曲定位到对应样本后按需继续。实时玩家模式继续禁止无输入记录 Seek。音频结束和 Sequence 结束分别处理，歌曲结束后若战斗仍未结束，则无跳变地切换到固定时间推进；默认不因歌停而冻结世界。

编辑器后端隔离 AudioUtil 反射，探测 PlayPreviewClip、Pause/Resume、SamplePosition 和定位能力。所有引用留在 Editor，关闭窗口/切换资产/进入 PlayMode/domain reload 时清理自己发起的试听状态。这个 Unity API 的停止函数是全局预览停止，编辑器不能保证同时存在多个独立试听，UI 明确采用单个活动音乐预览。

第一版音频模式 1x，避免内部试听 API 没有 pitch 参数而导致逻辑倍速和音乐不一致。若目标中国版 2022.3 的试听采样定位无法可靠使用，要先解决适配验证，再交付同步功能，不能以不同步试听宣称完成。

实战音量注册 Music 通道。编辑器提供本窗口监听音量/静音控制所需的可用后端能力；若 AudioUtil 无独立音量，沿用编辑器音量设置，不伪造每源音量控制。

**九、验收与验证**

战斗：

- 常规/散射的发射数量、角度、10 秒内累计发射次数符合相同调度约定；射速测试覆盖 5、2.5 和 8 次/秒，8 次/秒只验证调度器，不表示跟踪玩法完成。
- 同输入在 30/60/144 FPS 下执行相同 Tick 后状态一致；松开/重新按下不补发积压子弹。
- 玩家弹只伤 Boss，敌弹只伤玩家；同阵营无伤害；同 Tick 扫掠与 Enter 不重复伤害。
- 高速弹穿过受击圈仍命中，玩家和目标移动时仍正确；单弹命中次数耗尽后不能继续伤其他对象。
- Sequence 结束后残留弹继续移动，角色继续射击；ClearAtEnd 不清角色弹。
- 暂停不积累逻辑时间，恢复不集中补跑；玩家/Boss 死亡事件只产生一次。
- 原分裂、随机种子、固定预览 Seek、对象回收和 Sprite 批绘制验证保留。

音频数值：

- 静音没有标记；已知低/中/高频脉冲在对应频段出现，位置误差按 FFT/Hop/补偿参数定义并检查。
- 单声道、立体声、反相双声道、44.1k/48k、短于 FFT 窗口、长歌、尾部均覆盖。
- SampleFrame→秒→Tick 与反向定位使用共享函数；音乐偏移和同 Tick 多标记正常。
- 源音频或参数改变使缓存过期；取消/失败不损坏旧结果；Streaming 分析副本不改变源导入策略。

音频集成：

- 编辑器和实战使用同一资产及时间映射，同一 Tick 的 Boss 模拟状态一致。
- 播放、暂停、拖动、循环、换曲、窗口关闭和进入 PlayMode 时不残留试听。
- 实际记录音乐源位置与游标/逻辑时间的差值。正常推进下逻辑量化误差目标为一个 Tick；可见帧延迟、音频缓冲和设备输出延迟单独测量，不宣称采样级画面同步。
- 音频开启时编辑器和实战均 1x；无音频的现有倍速保持可用。
- 既有 Master/Music 音量设置在实战生效；分析器代码不进入 Player 构建。

**十、技术依据**

- Unity 2022.3 AudioClip.GetData：交错多声道、读取失败返回 false、越界读取回绕、压缩/Streaming 限制。https://docs.unity3d.com/2022.3/Documentation/ScriptReference/AudioClip.GetData.html
- Unity 2022.3 AudioSource.PlayScheduled：基于 DSP 绝对时间调度，独立于帧率。https://docs.unity3d.com/2022.3/Documentation/ScriptReference/AudioSource.PlayScheduled.html
- Unity 2022.3 AudioSource.timeSamples：PCM 样本位置与定位。https://docs.unity3d.com/2022.3/Documentation/ScriptReference/AudioSource-timeSamples.html
- Unity 2022.3 官方源码 AudioUtil：internal 编辑器试听 API，支持开始、暂停、恢复与样本定位，没有独立 pitch 参数。https://github.com/Unity-Technologies/UnityCsReference/blob/2022.3/Editor/Mono/Audio/Bindings/AudioUtil.bindings.cs
