# 节拍器实际音频输出验收

日期：2026-10-12；Unity 2022.3.62f1c1；Windows x64 Mono Development Player。

## 原因与行为

旧提示音长 20 ms，衰减时间约 3 ms，AudioSource 基础音量为 0.45；歌曲预览保持完整音量，较短的提示音容易被歌曲掩盖。暂停时勾选开关只配置调度，不开始试听，也没有可观察的每拍反馈。检查当前音量设置均为 100，未静音。

现在提示音为 50 ms、1 ms 渐入、12 ms 衰减、2200/3300 Hz 两个频率，基础音量为 0.85。节拍器播放时仅将当前歌曲预览降低到正常音量的 30%；关闭、暂停或退出页面恢复音量。AudioVolumeService 保留基础音量与临时 gain，保证全局音量更新不会覆盖衰减，也不会叠乘已缩放的音量。

在有效音频和有效 BPM/首拍下，勾选节拍器从当前位置自动开始试听。每拍显示递增拍数并短暂变为橙色，暂停时显示“已开启 · 已暂停”。总音量或音效音量为 0 时显示原因并保持静音。节拍和歌曲继续共用 DSP 时钟，未添加每帧直接播放的提示音。

## Windows 实际输出

先确认桌面音频基线 RMS 与峰值均为 0；实际鼠标导入合成 440 Hz WAV，点击节拍器开关。通过默认播放设备的 WASAPI loopback 录制 48 kHz 双声道音频，捕获到实际设备混音输出；没有使用 UI 回调模拟替代输入。

| 检查 | 实测结果 |
| --- | --- |
| 暂停时开启 | 自动播放，开关勾选，播放按钮变为暂停 |
| 120 BPM，开启录音 5 秒 | 10 次 2200 Hz 节拍提示峰，间隔中位数 0.500 秒 |
| 关闭录音 3 秒 | 未检测到提示峰，2200 Hz 幅度峰降至约 0.000021 |
| 歌曲音量开/关比 | Unity 预览增益 0.30；设备输出的 440 Hz 中位幅度比约 0.323 |
| 离开对齐页再从列表试听 | 音量恢复，无节拍提示峰；2200 Hz 幅度峰约 0.000022 |
| 155 BPM 的 MP3，开启录音 5 秒 | 13 次提示峰，间隔中位数 0.390 秒，理论值 60/155≈0.387 秒 |
| UI 反馈 | 实际观察到拍数递增和橙色闪动；暂停后再开启，从暂停位置继续 |
| 保存或返回 | 调度停止，当前预览增益恢复为 1 |
| 异常 | 本轮 `interaction-errors.txt` 为 0 字节，最终预览停止 |

幅度与间隔估算使用 20 ms Hann 窗、10 ms 步长。播放设备输出受设备处理影响，以上幅度比与 Unity 源增益分别记录，不将二者等同。此验证不包含声卡、扬声器或耳机的物理延迟测量。

Windows 验证播放器使用独立测试存档。主项目保留正式音频与歌曲参数；刷新旧 Play 实例之前先将观察到的未保存 BPM/首拍草稿备份到忽略目录，刷新后恢复草稿，未执行正式歌曲的保存操作。
