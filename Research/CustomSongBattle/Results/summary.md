## 本机操作覆盖

通过操作系统窗口输入，从主菜单进入“我的音乐”，打开原生文件选择器并取消，然后导入包含中文、空格和 `#` 的 `节拍测试 # 共鸣舞台.wav`。未保存有效对齐时“进入挑战”不可用；保存 120 BPM、首拍后可以进入准备页。90 秒测试曲生成低频 28 轮、中频 22 轮、高频 20 轮。

实际进入战斗后观察到倒数、频段预警、音乐背景、玩家与敌弹。站立不躲避时真实弹幕碰撞导致死亡，进入“未完成”结算，保存歌曲成绩且没有道具掉落。通过按钮重试、暂停和恢复，最后返回歌曲库。重启后歌曲、对齐和记录仍可读取。最终版本再次操作短曲及返回，确认失败评级单行显示。

手动窗口输入没有取得可计入验收的持续开火命中结果，因此没有将它列为手动射击通过项。普通及节拍命中由独立程序 Input System 输入验证；角色移动、跳跃、飞行等由原有 PlayMode 输入测试覆盖。这些验证方式在本报告中分别记录。

## 三频与同步数据

使用 22,050 Hz 单声道合成信号，主频分别为 100、800、4,500 Hz，另含很弱的 421 Hz 播放参考音。12 秒输入最终编排结果如下。

| 输入 | 低频轮数 | 中频轮数 | 高频轮数 |
| --- | ---: | ---: | ---: |
| low | 9 | 0 | 0 |
| mid | 0 | 9 | 0 |
| high | 0 | 0 | 9 |
| mixed_short | 4 | 2 | 3 |
| 项目已有 MP3，约 120.72 秒 | 38 | 10 | 39 |

自动流程实测 Boss 命中 57 次，其中节拍奖励命中 35 次，观察到敌弹峰值 34。采样到的音乐位置与逻辑 Tick 最大差约 16.62 毫秒，最大单帧约 20.94 毫秒。这些数值来自一台机器的一次短曲运行；它们是回归证据，不代表长曲、低配机器或其他平台的性能上限。

默认播放设备回环的 421 Hz 参考幅度中位数：播放 `0.0317537`，暂停 `5.72e-12`，恢复 `0.0317554`。暂停前后状态均为 Tick 689、音乐位置 11.4839909297 秒，保持不变，详见 [暂停前](paused-before.json) 与 [暂停后](paused-after.json)。采样没有使用麦克风或保留原始录音；这验证了播放和暂停控制，没有测量键盘到扬声器、蓝牙耳机等物理链路延迟。

## 本轮修复及回归

- 纯高频信号的弱低频泄漏此前被独立归一化为强候选。增加相对峰值筛选和归一化下限后，纯频输入各自正确驱动对应类型。
- 起音时间有毫秒级抖动时，以浮点秒数做冷却可能持续跳过同一组候选。冷却改为实际 60 Hz Tick，混合频段再次保持三类攻击。
- “未完成”在原评级容器中换行。自定义评级改用单行自动字号，正式歌曲保持原字号规则。
- 重试倒数时保留上一局死亡 HUD。开始倒数前渲染新角色的初始生命和体力，清除死亡提示。
- 原有玩家测试的存档共享、启动音乐覆盖静音夹具、写死无敌圈颜色导致 5 项回归失败。测试现在隔离存档并使用实际配置。
- 正常游戏包沿用保存的 2560×1440 窗口，而当前桌面为 1920×1080，导致右侧入口和底部按钮在屏幕外。窗口模式现在按当前桌面等比例缩小，并为标题栏与任务栏留出空间；原保存参数及全屏/无边框模式保持原逻辑。新增 `SavedLargeWindowRemainsVisibleAfterMovingToSmallerDesktop` 回归测试，最终全套 19 项通过。
